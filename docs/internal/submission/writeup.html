Why we built it, and the problem it solves

Nexconn ships chat SDKs for Android, iOS, the Web and Flutter, but nothing for React Native, one of the most widely used ways to build mobile apps. A React Native team that wants Nexconn today must write and maintain two native bridges, in Kotlin and Swift, and re-solve the same hard problems on each:

  • delivering SDK callbacks safely across threads, and surviving JavaScript reloads without registering handlers twice;
  • keeping a previous user's late callbacks out of the next user's session after an account switch;
  • matching a message's local echo to the server's acknowledgement without duplicates, and retrying failed sends without sending twice;
  • smoothing over the places where the Android and iOS SDKs behave differently.

We built a reusable, open-source library so that any React Native or Expo developer can add Nexconn chat by installing one package and using familiar React hooks. It is not a single app: it's infrastructure that makes every future React Native Nexconn app faster to build and more reliable. The demo app shows it working end to end.

Features that use the Nexconn SDK

The library bridges the official Nexconn SDKs, ai.nexconn.chat:chat 26.4.2 (Android) and NexconnChat 26.4.2 (iOS), and covers their public surface: 159 bridge methods, 18 paged query kinds and 67 events. The demo app uses these features:

How it works

React components
  │  hooks: messages, channels, groups, users, drafts, search, push …
  ▼
NexconnClient (TypeScript): typed modules, errors, paged queries
  │  one JSON protocol: invoke(method, args) + one event stream
  ▼
TurboModule (React Native New Architecture)
  ├─ Android: Kotlin bridge → ai.nexconn.chat:chat 26.4.2
  └─ iOS:     Swift bridge  → NexconnChat 26.4.2
  • Session generations. Every connect and disconnect bumps a generation number carried by every event, so callbacks from a previous user never reach the next one.
  • No fake success. If a platform's SDK has no equivalent for a call, it fails with a typed unsupported error. A parity matrix generated from the source lists every method per platform.
  • Retry that can't duplicate. A failed message stays on screen with its error. Retry is offered only once the SDK itself reports the send as failed.
  • Read state from real receipts. Testing showed that the Android SDK reports receipts but keeps the stored message at "Sent", so the hooks track the SDK's receipt counts.
  • Measured performance. Profiling the message list made live message handling about 80 times faster (379 µs to 4.5 µs per message in a 2,000-message list).

Trying it

Demo app (Android)

  • Download the APK from the link above and install it on an Android 7+ phone or emulator (allow installs from unknown sources).
  • The App Key and server are filled in. Sign in as judge1. To chat with yourself, sign in as judge2 on a second device or emulator, then type judge2 on the Chats tab and tap Chat.
  • Tap a message for actions: reply, edit, recall, retry. Use the Members button in a group, and the Contacts and Playground tabs.
  • The sign-in server runs on a free host that sleeps when idle, so the first sign-in can take up to a minute.

Library

npm install @subramanyarao11/react-native-nexconn

The documentation site has a quickstart for Community CLI and Expo, a reference for every hook, and troubleshooting.
